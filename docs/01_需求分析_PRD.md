# 01｜需求分析（PRD）

> 持仓雷达 Stock Radar · PRD v0.1 · 2026-11-20

## 1. 项目背景

### 1.1 现状

用户在同花顺使用 KDJ、净利润增长、资产负债率等条件自行选股，并通过已有券商/交易软件买入；买入后，需要逐只打开走势图与 RSI、KDJ 等指标才能判断何时关注卖出。一旦忙碌、外出或忘记查看，很容易错过预定的技术信号。

录音讨论过量化回测、自动选股、A 股全市场筛选和 AI 策略，但双方最终收敛的目标是：**自己负责买入，只要求外部程序对持仓股票持续进行卖出风险监控和提醒。**

### 1.2 目标（Goals）

G1. 维护一组个人已持有股票代码（首期约 6 只，可扩展至 30 只）。  
G2. 每个交易日收盘后自动获取足够日 K 线，计算 RSI6/12/24。  
G3. 准确触发 RSI 超买或高位死叉信号，保存触发事件，避免同一事件反复推送。  
G4. 通过微信收到异常/风险提示；即使通知失败，也可在手机页面查看。  
G5. 手机浏览器直接打开并添加到桌面，无需 App Store 或微信小程序审核。  
G6. 最低数据成本、可替换行情提供方、保留进一步完善策略能力。

### 1.3 不在 V1 范围（Non-goals）

- 不支持股票买入、资金划转、券商账号接入或自动交易。
- 不做全市场选股（数千只股票扫描）、复杂策略优化和盈利承诺。
- 不强制开发微信小程序、Android/iOS 原生包。
- 不做分钟级/秒级量化交易；盘中扫描为可选 V1.5。
- 不收集银行卡、交易密码、券商口令等隐私信息。

## 2. 用户及使用场景

| 角色 | 权限 | 设备 | 核心需求 |
|---|---|---|---|
| 持仓使用者（父亲） | 查看、添加/停用持仓、手动检查、调整规则开关 | 手机 | 简单、醒目、能收到微信提醒 |
| 项目维护者 | 部署、更新、查看技术日志、处理错误 | Mac / GitHub / 服务器 | 可维护、低费用、接口可替换 |

### 2.1 场景 A：买入后登记

- 用户在同花顺选中并买入一只股票。
- 在持仓雷达输入六位代码（建议自动完成市场后缀）、确认股票名称后添加。
- 系统验证代码及市场，若重复则提示“已在监控”；保存时间和可选备注。
- 新股票加入下一次例行任务；如立即请求检测则按手动检查处理。

### 2.2 场景 B：每天自动监控

- 工作日按交易日历运行；首版默认 15:45（上海时间）检查，若最新日线未就绪，可延后到 16:15/16:45 重试；具体以接口实际更新时点为准。
- 从缓存或数据提供方获取最近至少 100 个交易日的日线，做数据完整性、价格有效性、时序校验。
- 计算 RSI，生成规则命中事件；保存输出、数据来源、数据日期与版本。
- 仅首次出现的新风险事件推送微信；同一交易日重复扫描不重复通知。
- 未产生卖出信号时页面显示“未检测到规则触发”，不代表未来上涨或风险为零。

### 2.3 场景 C：手机查看和手动刷新

- 在桌面点击“持仓雷达”，看到持仓数量、正在预警数量、上次检测时间、失败数量。
- 股票卡片展示代码/名称、RSI6/12/24、状态、最新收盘日、触发的规则。
- 可查看 RSI 曲线及信号历史，明确显示真实/演示数据和数据更新时间。
- 点击“立即检测”：向后端发起有权限、有防刷限制的检查任务；完成后刷新结果；不进行交易。

### 2.4 场景 D：接口失效

- 若接口 401/403、额度不足、网络超时、B 股接口失效、返回空数组或日期陈旧，页面标为“取数失败/行情未更新”。
- 不允许用过期指标冒充今日信号；不触发新的卖出提醒。
- 后端保存错误码与可读原因，允许人工重试；可发送合并后的“监控异常”通知（节流）。

## 4. 核心业务规则

1. **股票池**：使用者手工登记的持仓，不是全 A 股。`688525.SH` 是示例格式，不代表永久持仓。不得未经确认把手写图片中的所有数字自动加入真实持仓。
2. **交易日**：A/B 股交易日以中国证券市场交易日历为准；节假日不出当日收盘结果，页面保留最近的成功检测日期。
3. **数据频率**：V1 使用完成收盘的日 K 线；不要将盘中快照直接覆盖当日正式日 K 线来触发收盘信号。
4. **信号触发**：阈值穿越事件与持续状态分离；持续超买只展示状态，不每天重复推送。
5. **信号等级**：上破 80 → “关注”；高位死叉 → “风险预警”；两条同一天可以合并成一条通知。
6. **再次触发**：新交易日重新完成穿越后可产生新事件；同一股票同一规则同一交易日同一规则版本只记录一次。
7. **规则扩展**：顶背离/双重顶 V2 才启用，不能使用模糊描述造成随机触发。
8. **风险声明**：提示为基于规则的技术信号，不是系统自动下单或保证盈利。

详见 `03_RSI策略与计算口径.md`。

## 5. 非功能需求（NFR）

- **可用性**：手机主流浏览器（iOS Safari、Android Chrome/微信内置浏览器）访问成功；PWA 添加桌面在支持的浏览器实现。
- **响应**：缓存的首页请求在普通网络下目标 2 秒内显示；六只股票手动检测的完成时间取决于第三方接口，不做无依据的实时保证。
- **可靠性**：即使行情接口异常，已有历史记录不损坏；同一周期任务不得并发互相覆盖；失败指数退避但避免刷额度。
- **可维护性**：行情适配器独立；RSI/策略独立纯函数；核心逻辑有单元测试。
- **安全性**：所有密钥只在服务端；后端登录鉴权 + HTTPS + CORS 白名单 + 访问限流；不公开持仓 API。
- **成本**：以六只持仓、每日 1–3 次请求设计缓存/批量；数据/API/推送费用超过预设预算时停止自动扩频，先人工确认。
- **正确性**：检测结果保存 `bar_date`、`fetched_at`、`provider`、`adjustment`、`strategy_version`；缺失必需字段时报错。
- **隐私**：股票代码和备注为个人持仓信息；源代码可公开，生产持仓数据库与凭证不能公开。

## 6. 页面与交互需求

### 页面 1：持仓总览（默认）

- 标题“持仓雷达”；最近检测时间、行情交易日、总股票数、风险预警数、检测异常数。
- 按风险等级将股票排序，卡片：名称、代码、板块/市场、状态标签、RSI6/12/24、最近检测时间。
- “添加股票”“立即检测”“查看提醒历史”“设置”入口。
- 无股票状态、后台不可用状态、行情故障状态、演示数据状态设计完整。

### 页面 2：股票详情

- 近 3/6 个月 K 线，下面 RSI6/12/24 曲线及 20/80 参考线。
- 已触发规则名称、计算依据（前/当前 RSI 值）、触发日期、数据源。
- 可切换规则，不进行交易；明确是否为历史信号。

### 页面 3：持仓维护与配置

- 六位代码 + 市场；股票名称可由受支持的代码检索服务解析，失败则手工确认。
- 添加/停用/删除；删除前二次确认；不要求输入持仓成本或买入金额。
- 规则阈值默认超买 80、高位 70；仅管理员可修改。

### 页面 4：通知和健康状态

- 通知历史、发送成功/失败、通道状态、当日数据是否更新；不展示 API Key。

## 7. 主要边界与例外

- 同花顺 A 股批量历史 API 对未知/不支持标的可能在外层成功时**省略个股数据组**，不能将缺失标的当作成功。
- B 股历史日线经 AKShare 间接取自新浪财经，限流、封禁、字段变化应视为可能的外部风险。
- 复权口径必须统一，尤其分红送转前后，指标可能与同花顺终端不一致；对比时必须确认相同复权/时间范围。
- 同花顺 B 股授权不明确，V1 不宣称官方同花顺 API 覆盖 B 股。
- 用户仅需微信提醒，不保证微信订阅消息资格，采用 Server酱作为可替换通道。

## 8. MVP 验收条件

**全部满足才可称 V1 可用：**

1. A 股、B 股各至少一只真实股票在目标运行环境返回有有效日期与收盘价的非空数据（如某源无法测试，则该源标为待验证并禁止假装支持）。
2. 以 ≥100 个交易日历史数据计算 RSI6/12/24；至少挑选 3 个交易日与同花顺终端核对，记录公式差异。
3. 规则单测覆盖不穿越、刚上穿、持续超买、刚死叉、非高位死叉、空数据。
4. 新增持仓后刷新浏览器不会丢失；未登录不可访问。
5. 自动任务可真实运行；制造模拟信号能正确推送微信；同一事件只推送一次。
6. 行情断网/429/超时/空数据时，显示数据故障而非“正常”。
7. 手机可打开页面，能添加/删除股票、查看最新信号；至少在目标手机上完成一次端到端验收。
8. Git 仓库不包含密钥、数据库或个人真实持仓。

## 9. 需求限制与待确认项

- **实际六只持仓**：讨论中出现若干股票代码，但并非全部精确核对，不应凭手写照片推断最终列表。
- **股票市场**：A + B 预期支持；B 股类型、确切代码需用户亲自录入。
- **提醒时间**：默认收盘后 15:45 + 延迟重试；以实际数据源更新延时为准可改。
- **数据 API 费用、可用额度**：需要使用账号实测后填写；本 PRD 不保证免费无限调用。
- **云服务器/微信提醒**：首期部署成本未锁定，先从无服务器的接口探测阶段开始。
## V1.1 交易日持仓监控

交易日 14:30 向用户发送覆盖全部启用持仓的中文简报。有效盘中行情可触发即时预警，收盘数据确认最终状态。行情失效、消息限额、重复通知和持仓移除均有独立处理。每源默认每日最多 30 次物理 HTTP 请求，微信默认每天 5 次并为简报保留额度。调度、启用条件、测试及回退流程见 [V1.1 运行与维护](V1.1运行与维护.md)。

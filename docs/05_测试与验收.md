# 05｜测试策略、用例与验收计划

## 1. 测试金字塔

1. **纯函数单元测试**：RSI、规则判定、代码转换、日期与复权；不依赖网络。
2. **Provider 契约测试**：使用存档/匿名 fixtures 验证 HTTP API 外层信封、未知代码组缺失、API 错误码、B 股空表与列变化。
3. **真实网络集成测试（显式执行）**：A 股真实 Key + B 股实际 AKShare，成功后将脱敏结果写 `reports/`。
4. **后端集成测试**：数据库持仓 CRUD、并发调度、事件去重、通知失败重试，测试数据库使用临时路径。
5. **手机端 E2E**：打开页面、登录、添加/删除、检查指标、模拟信号、推送微信、页面健康状态。

## 2. 必须覆盖的单元测试

| Case | 输入 | 预期 |
|---|---|---|
| RSI-01 | 单调上涨 | RSI 接近/等于 100，未成熟期为 null |
| RSI-02 | 单调下跌 | RSI 接近/等于 0 |
| RSI-03 | 完全不变 | RSI=50（本项目约定） |
| RSI-04 | 数据长度不足 25 | RSI24 不可用于决策 |
| RSI-05 | 收盘价包含 0/负/NaN | 拒绝数据 |
| SIG-01 | 79 -> 81 | R1 命中 |
| SIG-02 | 81 -> 82 | 不重复 R1 |
| SIG-03 | 81/77 -> 75/78 | R2 命中 |
| SIG-04 | 60/55 -> 50/56 | R2 不命中，非高位 |
| SIG-05 | 交叉前 RSI6=null | 不产生事件 |
| SIG-06 | 复扫同日期同规则 | DB 去重，只发送一次 |
| API-01 | code=0 但缺某股票组 | 缺失股票显示错误 |
| API-02 | code 非 0 / HTTP 429/401 | 显示错误，不生成信号 |
| DATA-01 | 日线重复日期 | 去重记录、测试稳定 |
| DATA-02 | 数据过期 | 数据过旧状态，不推新信号 |

## 3. 探测报告验收

- 记录 `provider`、`symbol`、`status`、`bar_count`、`first_date`、`last_date`、`last_close`、`http_status`（如有）、耗时、错误分类。
- API Key、Server酱 SendKey 不在输出中，URL 不含敏感查询串。
- A 股多代码请求需要检查每个代码各有结果；如果只返回 1 组，另一组报告 `SYMBOL_MISSING`。
- B 股在常用 Mac Python 环境和计划使用的云主机上分别验证。
- 接口若不可用，程序返回非零退出码，`reports/` 仍保留脱敏错误摘要。

## 4. 策略核对

使用同花顺终端至少 3 个不同交易日的 RSI6、RSI12、RSI24，记录四项：终端数值、程序数值、差异、复权方式。理想情况下差异可小于 0.5 RSI 点，若不能达到，必须查明初始化/复权原因，不能简单改变阈值掩盖问题。跨源 B 股也要尽可能核对。

## 5. 定时与推送验收

- 在测试环境人工触发定时任务，确认行情处理和结果保存。
- 用**明确的模拟数据**制造一次 R1、一次 R2，不要等待真实股票触发。
- 同一批次合并推送；重复运行不会再发送。
- Server酱故障时记录失败，重新投递有最大次数和退避；不能无限循环。
- 收盘后 15:45 若数据尚未更新，按计划重试；超过窗口转 `DATA_STALE` 并可选通知一次“监控异常”。
- 任务遇到 B 股异常时，不影响 A 股的单股检测、存储和推送。

## 6. UX 验收（必须在真机）

- 首页首次加载有 loading；断网出现可理解错误；旧数据标出日期。
- 6 位股票代码输入错误、A/B 市场不匹配，有直接提示。
- iPhone Safari 与安卓至少各测试一种；如果只有一台手机，明确记录未覆盖项。
- 小屏幕（宽 360px）无横向溢出、可触达按钮、无过小字体。
- 添加到手机桌面不影响登录和查看。

## 7. 上线门槛与回归

- `python -m unittest discover -s tests -v` 全绿；后续 `pytest` 前后端单测和 CI 全绿。
- 编译、类型检查、lint、前端构建通过；环境变量没有打包进前端 JS。
- 明确网页真实域名与后端域名；未登录不能查询个人持仓。
- 不含真实交易密码、账号与持仓记录；数据库与 `.env` 未进入 Git 历史。
- 手动测通至少一次真实数据 + 一次模拟推送 + 一次真实手机访问。

# Stock Radar V1.1 运行与维护

## 手机使用

在[持仓雷达](https://lipume.github.io/stock-radar/)使用原密码登录。首页按风险排序，逐股显示核实的中文名称、代码、币种、价格、行情日期和 RSI6、RSI12、RSI24。「信号记录」提供盘中信号出现、解除、收盘确认、每日简报和微信投递回执。卖出后可在个股详情底部删除持仓，已记录的事件保留。

日 K 价格图叠加 5 日、10 日和 20 日简单移动均线，下方单独显示 RSI。均线取最近相应个数有效交易日的前复权收盘价的算术平均。获验证的盘中报价只作为当天的一个暂定价格，收盘后由正式日线替代。持仓卡和简报按行情日期列出三条均线，价格、百分比、RSI 和均线显示两位小数，历史不足的周期显示缺值。均线供读图参考，预警条件仍是两条 RSI 规则。

## 交易日运行计划

| 北京时间 | 任务 | 默认行为 |
|---|---|---|
| 10:00、10:30、11:00、11:30、13:00、13:30、14:00 | 盘中检测 | 核验行情并开启自动检测后运行 |
| 14:30 | 完整持仓简报 | 与同一时刻的检测共享一轮。行情未核实时逐只显示最近有效收盘及日期 |
| 15:45 | 正式收盘检测 | 按前复权日线确认结果 |
| 16:15、16:45 | 延迟行情重试 | 只重试仍启用监控且行情滞后的标的 |

在「设置」可调整盘中间隔（15、30、60 分钟）、简报时间、两类即时通知开关，以及微信和行情预算。缺少已公布的当年交易日历时暂停定时任务。日历维护入口为 `scripts/market_probe.py`，新年开始前应依据沪深交易所公告补充休市日期和年度边界测试。系统使用 Asia/Shanghai 时区。

## 数据核验与策略维护

正式收盘使用同花顺 A 股批量日线和 AKShare 新浪 B 股前复权日线。每轮盘中计算读取上一正式交易日使用的历史窗口和一个临时当日价格。逐股报价须有可靠的当日成交时间、币种、完整价格、可核实的除权口径及可比前收。行情批次和 HTTP 响应的时间无法证明单股成交时间。B 股可独立降级为正式收盘监控。

上线默认使用 `INTRADAY_VALIDATED=false`。确认权益与请求限制后，在香港服务器通过独立库比对交易时段内的逐股成交时间、成交价、除权前后前收及终端 RSI。适配器接受供应商确认语义的 Unix 毫秒级逐股成交时间字段，可配置为 `HITHINK_VERIFIED_ROW_TIME_FIELD`。上游缺少该字段时，应先取得有相应字段的授权行情。核验通过后才可开启后端环境开关并在页面启用自动检测。调度主开关为 `SCHEDULER_ENABLED`。

两条生产规则共用 `src/stock_radar/rules/rsi.py`。调整上破阈值和高位门槛可直接使用设置页面。修改规则逻辑时更新策略版本，并在日线、盘中回归测试中对照交叉前后的 RSI。盘中记录和正式日线分表。证券中文名称由行情提供，或由 `SECURITY_MASTER_FILE` 指定的私有 JSON 映射提供，每项包含 `name` 和核实来源 `source`。

交易日复验时，在新版本目录中执行以下两个命令。使用最近的独立在线备份和同一个私有验证台账；只有需要重新探测 B 股候选源时才加 `--probe-b`。终端对照文件记录每只股票同一行情时刻的价格和三个 RSI 值。

~~~sh
python -m scripts.verify_intraday_source capture --backup /private/latest.db --ledger-dir /private/validation --out /private/capture.json
python -m scripts.verify_intraday_source compare --capture /private/capture.json --reference /private/terminal.json --out /private/comparison.json
~~~

## 请求与消息额度

每源每天默认限 30 次物理 HTTP 请求。收盘、快照、分页和超时重试共用持久化计数。普通检测为简报及正式收盘预留请求，触限时显示原因。页面只访问后台缓存。微信每天默认最多 5 次，日报预留 1 次，同轮信号合并。发送结果不确定的请求保存未知回执，以免重发。

在部署的应用目录运行 `python3 scripts/monitor_usage.py /var/lib/stock-radar/stock_radar.db --days 7`。该命令按北京时间只读汇总物理请求、限流、缓存、消息抑制及回执。用满一周实际数据后再评估检测频率。

## 部署、迁移与回退

采用单个 Uvicorn worker，监听 127.0.0.1:8765，经 Caddy 提供 HTTPS。GitHub Pages 在后端测试与前端构建通过后发布。PWA 自动更新静态资源。浏览器缓存应用外壳，私人 API 需要鉴权。

部署前用 SQLite 在线备份，在另一文件中实际恢复并检查完整性及旧表指纹。单独保存后端环境、管理员哈希和服务配置。先在独立库执行升级、降级、再次升级及全部测试，禁用真实通知。停写时保存最终快照，核对升级后旧表原有列与行的指纹。重启后检查健康、匿名 401、中文名称、下次计划及备份定时器。

回退时先停止调度及写入，备份新版现场，再恢复配对的旧库、应用版本、服务配置与凭据。保留回退点以后新增的业务数据。私有验收记录保存在本机 `reports/v1.1/`。

# 03｜RSI 策略详细规则与计算口径

> 规则版本 `rsi-v1.0`。源自用户提供的同花顺 RSI 技术指标截图第 2、4、6、8 条（看跌提示）。V1 默认正式启用前两条，其余作为 V2。

## 1. 特别纠正术语

**超买（overbought）不是超卖（oversold）。** 录音里提到“RSI 超卖时卖出”，但截图第 2 条表达的是 RSI6 >80 时**超买**，以及高位死叉、双重顶、顶背离。超卖通常是 RSI6 低于 20/30，不能机械当作卖出信号。

## 2. 指标输入与计算

数据源：日频收盘价、至少 100 个有效交易日（建议 180 日），按交易日升序；复权口径默认前复权 (`forward`/`qfq`)。不把快照价格直接混入正式收盘序列。

V1 参考实现选用 **Wilder 平滑 RSI**：

- `change_t = close_t - close_(t-1)`，`gain_t = max(change_t,0)`，`loss_t = max(-change_t,0)`。
- 前 `n` 个变动的平均涨跌幅用于初始值：`avg_gain_n = mean(gain_1..gain_n)`，`avg_loss_n = mean(loss_1..loss_n)`。
- 后续 `avg_gain_t = (avg_gain_(t-1)*(n-1) + gain_t)/n`，亏损同理。
- `RS = avg_gain/avg_loss`；`RSI_n = 100 - 100/(1+RS)`。
- `avg_loss=0, avg_gain>0 => 100`；`avg_loss>0, avg_gain=0 => 0`；二者都为 0（价格完全不变）=> 50（明确约定，需与同花顺屏幕校对）。
- `t<n` 返回 `null`，不允许填 0 或前向填充。计算 RSI6/12/24。

**重要**：同花顺经典指标公式常使用 `SMA(MAX(C-LC,0),N,1) / SMA(ABS(C-LC),N,1) * 100`，其**初始化**可能与 Wilder 第一段种子不同，尤其在较少 K 线下数值不同。因此实际发布前需要抓 ≥100 天日线和终端曲线核对，必要时新增 `tonghuashun_sma` 兼容模式，不能声称现参考实现已完全匹配同花顺。

## 3. V1 规则

### R1：RSI6 进入超买（关注级别）

```text
prev_rsi6 <= 80 AND curr_rsi6 > 80
```

- 这是**事件**（首次突破），不是 `curr_rsi6 > 80` 每天发一次消息。
- 页面持续展示“RSI 超买中”直到跌回或等于 80，重新上破时允许再次通知。
- 若刚启用监控且当前 RSI6 已 >80，但没有有效昨日 RSI 值：只显示“当前超买”，不伪造历史首次突破事件。
- 等于 80 不算“>80”。

### R2：RSI 高位死叉（风险预警级别）

```text
prev_rsi6 >= prev_rsi12
AND curr_rsi6 < curr_rsi12
AND prev_rsi6 >= 70
```

- “高位”未被用户截图给出具体阈值；**70 是项目定义的可配置默认阈值**。
- 前日 RSI6 高位、前日 RSI6 不低于 RSI12、今日向下跌破 RSI12，触发一次。
- 交叉发生在 RSI6=30 附近不应触发“高位死叉”。
- 若两规则同日触发，生成两条 `SignalEvent`，但合并为一条微信消息。

### R3：状态与风险等级

- `ALERT`：当天有 R2 新信号；
- `WATCH`：有 R1 新信号或 RSI6 持续 >80（即使本日无新事件）；
- `NO_RULE_TRIGGERED`：行情有效但未触发启用规则；
- `DATA_UNAVAILABLE` / `STALE` / `INSUFFICIENT_DATA`：不能做出本日判断；优先级高于“正常”。

UI 应展示明细：日期、`rsi6_prev`、`rsi12_prev`、`rsi6_today`、`rsi12_today`、规则编码、版本及数据源。

## 4. V2 候选规则（不得在 V1 以模糊启发式启用）

### R3：RSI 双重顶

同花顺截图说“RSI6 连续两次上涨到同一位置遇到阻力回落，形成双重顶形态”。实现之前必须定义：峰的确认延迟、峰间最小距离、峰值容差、回撤幅度、突破颈线或跌破二峰后局部低点的确认条件；另需分析前瞻数据泄漏问题。提供可配置窗口和确定性测试后再启用。

### R4：RSI 顶背离

同花顺截图说“股价创新高同时 RSI 指标不能创新高”。实现之前必须明确：股价的峰值是最高价还是收盘价；峰值识别窗口；与 RSI 峰的时间对应容差；创新高幅度与 RSI 较低高点幅度；避免使用未来 K 线才能确认的峰。V2 写成独立单测后启用。

## 6. 去重和重算

- 事件唯一键：`holding_id + bar_date + rule_code + strategy_version`。
- 同一收盘 K 线重复检测、网络重试、用户多次点“立即检测”不得再次推送。
- 规则配置变更后，使用新 `strategy_version`；重算历史不等于立即推送历史消息。
- 停牌或数据过旧时不可当作今天产生的新穿越事件。

## 7. 实盘对齐计划

1. 各取 1 只 A 股、1 只 B 股约 180 根日线；同样前复权条件，复核三个交易日终端 RSI6/12/24。
2. 记录差异的绝对值/方向以及可能原因（平滑初始化、非交易日、当日未收盘价、前/后复权）。
3. 如果差异显著，以同花顺终端公式复现和测试为准，调整适配器而不是随意改阈值。
4. 将结果入 `reports/`，记录日期、终端截图/人工数值、脚本输出、结论，避免公开个人持仓截图。

## 第二阶段规则引擎

`stock_radar.rules.engine.evaluate_history` 接收已按日期和复权口径校验的收盘价序列。少于 100 根返回 INSUFFICIENT_DATA，满 100 根后比较最后两个交易日，返回 RSI6/12/24、前日数值和事件代码。只有上破和高位死叉参与 V1；双重顶、顶背离可实现 HistoryRule 接口，须经单独验证后注册。修改阈值会生成不同的规则版本。

阶段一验证通过 31 项离线测试，覆盖等于 80 的边界、前日两线相等、低位超卖和历史长度不足。

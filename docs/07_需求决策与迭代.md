## 尚未确认，不得擅自假设

1. 用户最终持仓股票代码清单（尤其手写图中不清晰处）；应让用户在界面自己录入。
2. 同花顺账号当前 API Key 的可用性、日线权限、额度、费用、云端 IP 限制。
3. B 股实时/日线实际运行环境稳定性、历史区间和复权口径。
4. 父亲手机的操作系统及网络环境，PWA 桌面安装是否顺畅。
5. 是否希望每天**无风险也推送日报**。默认只在新信号或监控失败时提醒，减少骚扰。
6. 具体部署平台、每月预算；不预先购买云服务器。
7. 是否开启盘中检测；默认不启用。

## 迭代路线图

- **阶段 0：数据可行性证明**：验证真实 A 股/B 股日线、认证、额度，输出独立报告和数据样例；无 Key 时保证离线 demo/单测能运行。
- **阶段 1：规则与后台 MVP**：数据标准化、RSI、R1/R2 信号、持仓数据库、健康状态、定时检测、Server酱。
- **阶段 2：手机 PWA**：总览、详情、持仓 CRUD、曲线、手动检测、登录与部署。
- **阶段 3：长期稳定性**：消息去重、异常补偿、数据对齐、正式手机测试、定期备份。
- **V2：策略升级**：顶背离、双重顶、KDJ、MACD、5 日均线、可选回放与策略对比。
- **V3：产品形态升级**：如果微信使用习惯更强，再考虑小程序和订阅消息资格；不必重写后端。

## 需要规避的误区

- 把 RSI“超卖”误写为“卖出”；
- 用未经授权的同花顺 SuperMind 研究环境函数冒充外部 REST API；
- 把 B 股全部当成 A 股接口能查；
- 把 `HTTP 200` 或 `code=0` 误认为每只股票都有历史日线；
- 直接把第三方 API Key 写在 Vue 代码或小程序包里；
- 页面显示实时价却实际只更新前一个交易日；
- 消息发送失败仍显示已提醒；
- 单机部署时开多个 APScheduler 实例；
- 过早做复杂 AI Agent，而最关键的行情正确性尚未通过检验。

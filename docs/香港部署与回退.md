# 香港 ECS 部署与回退

从 [Stock Radar 手机主页](https://lipume.github.io/stock-radar/) 登录。GitHub Pages 提供静态页面。香港 Caddy 为公网 IP 提供 HTTPS 并转发至回环地址上的 FastAPI。工作流读取仓库变量 `VITE_API_BASE_URL`，本仓库 main 默认使用 `https://8.217.211.34/api/v1`。后端 CORS 白名单为 `https://lipume.github.io`。

## 运行与备份

V1.1 增加交易日 14:30 持仓简报、行情与通知用量台账，继续使用原 HTTPS 和微信通道。升级门槛、单股时间戳及复权核验、独立库迁移与回退见 [V1.1 运行与维护](V1.1运行与维护.md)。

- Ubuntu 22.04 使用 uv 安装 Python 3.12，按锁文件安装 server 和 probe 依赖。通过 [systemd 单元](../deploy/systemd/stock-radar.service) 用 stockradar 运行一个 Uvicorn worker，监听 127.0.0.1:8765。
- 生产环境文件为 /etc/stock-radar/backend.env，权限 0600，归 root 所有。生产库与管理员密码哈希位于 /var/lib/stock-radar，归 stockradar 所有。私钥、真实配置、持仓、行情明细和数据库快照仅通过私有管理通道传递。
- 检测时区为 Asia/Shanghai。工作日 15:45 检测，按交易日历过滤休市日。微信是否投递取决于后端凭据、持久化的通知设置和新信号。交易日历变更时需在对应年度开始前核验。
- [备份定时器](../deploy/systemd/stock-radar-backup.timer) 在北京时间 03:15 执行 SQLite 在线快照。按天保留最近七份；同日重复执行复用已有快照。恢复演练使用新的独立路径。需要抗整盘故障时，另保留经校验的异地私有副本。
- Caddy v2.11.9 使用 Let’s Encrypt 的 shortlived 证书配置和公网 IP 的默认 SNI。安全组允许 TCP 80、443，应用端口 8765 仅绑定回环。核对证书剩余时间和自动续期日志。[IP 证书规则](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)

## 切换及回退顺序

1. 源端以 SQLite 在线备份生成快照，连同环境、管理员哈希和 systemd 单元安全传输。检查文件摘要、数据库完整性、外键、全表计数及逐条持仓状态。
2. 在目标独立库运行验收，单独指定数据库与哈希文件，关闭调度并从进程环境中移除微信凭据。运行自动化、两类真实行情和 RSI 比对，验证公网登录、匿名 401、持仓增删以及手动检测。
3. 冻结源端写入并停止源应用，核实没有进行中的检测和通知投递，再制作最终快照。在目标停止验收服务并安装最终数据。避免覆盖已有生产库，安装前检查 SQLite 的 WAL、SHM 和 journal 文件。
4. 启动目标生产服务和备份 timer。用正式 HTTPS 入口只读核对当前持仓、最新检测和设置，立即运行备份并独立恢复校验。旧端保留冻结标记，防止意外重启形成双调度。
5. 一旦目标已接受真实写入，回退前必须先冻结目标，从目标重新核对和迁回最新数据库、信号及投递状态，再恢复旧端服务。释放旧实例前核实独立备份能够重建服务。

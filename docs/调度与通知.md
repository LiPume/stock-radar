# 收盘检测与微信通知

## 检测时间

后端在上海时间 15:45 对启用的持仓运行一次收盘检测。16:15 和 16:45 两个重试时段只检查标记为 STALE 的启用持仓。当日 15:45 后启动服务时，如当天还没有主任务记录，补跑一次。生产环境需保持后端常驻；休眠和关机期间无法调度。

本版使用上交所公布的 2026 年交易日历。跨年度运行前需更新交易日历和对应测试，未覆盖年份会在任务记录中显示失败。盘前和休市日可手动读取最近一个完整收盘日，微信通知仅针对当日收盘事件。[上交所休市公告](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)

服务部署在 macOS 或 Linux，使用一个 Uvicorn worker。每个 SQLite 文件配有操作系统文件锁，重复启动实例会报错。单次检测互斥，点击间隔 30 秒。设置 `SCHEDULER_ENABLED=false` 可仅保留手动检测。

## 行情与记录

A 股以最多 10 只为一组取 240 个自然日的前复权日线，逐组检查标的和字段。B 股逐只通过 AKShare 从新浪取得前复权日线，单只总时限 45 秒，多只之间间隔至少 1 秒。对同一最新收盘日，最近 5 分钟成功取得并校验过的数据可在 SQLite 中复用。获取到新数据后，整个窗口在同一事务中替换，避免前复权因子变化导致历史价格口径混杂。

有效输入须有至少 100 根日线、完整且有效的交易日期和 OHLCV、正确时序、最新完整收盘日和上个交易日的收盘价。停牌或缺失上个交易日数据时，页面显示数据不足。个股失败会写入任务的异常摘要，保留历史日线并清除该持仓的当前指标。成功标的继续运行。

每个信号保存持仓、收盘日、规则代码、规则版本、RSI 证据和来源。数据库唯一约束保证重跑幂等。信号详情记载当时的阈值，历史配置变更后仍可回查。任务状态 SUCCESS、PARTIAL、FAILED 分别表示行情检测全部成功、部分成功和失败，推送服务商的处理结果单独记录。

## 配置微信

1. 在 Server酱 Turbo 中绑定接收渠道并获取 SendKey。[Server酱控制台](https://sct.ftqq.com/)
2. 将 `SERVERCHAN_SENDKEY` 写入后端环境，重启后端，然后在网页设置中打开微信通知。新建数据库默认关闭推送。
3. 验证通道时，在加载了后端环境变量的项目根目录执行下方命令。第一条只预览测试文案，第二条会向真实渠道发送一条标记为测试的通知并使用服务商额度。两条命令都独立于持仓和扫描历史。

```bash
.venv/bin/python -m backend.app.notifications
.venv/bin/python -m backend.app.notifications --send-test
```

同一轮的首次穿越事件合并为一条通知。相同持仓、日期和规则已记录时，即使调整阈值产生了新版本的审计行，也不会再次推送。持续超买可在页面显示“关注”。每个上海自然日，扫描服务最多发出 5 次请求，独立 CLI 通道测试及其他应用的用量由服务商另行统计。[官方额度与错误说明](https://sct.ftqq.com/docs/getting-started/faq/)

SENT 表示服务商返回业务码 0。HTTP 429 或非零业务码记为 FAILED。仅在 DNS 解析失败或连接被拒绝时延迟 1 秒重试一次；未取得回执的已发出请求记为 UNKNOWN，留待人工核查。发送意图在调用服务商前落库，进程中断后会保留未知状态。通知关闭、缺少 SendKey、额度用尽和过期事件均记录 SKIPPED 及原因。[Server酱 Python 接入文档](https://sct.ftqq.com/docs/integrations/python/)

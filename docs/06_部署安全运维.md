# 06｜部署、安全与运维指南

## 1. 环境划分

| 环境 | 内容 | 说明 |
|---|---|---|
| Local | 本机 Mac，脚本和后端测试，SQLite 临时库 | 可用真实 Key，但 `.env` 不入库 |
| Staging | 小型后端实例/临时域名；前端预览分支 | 用测试持仓和模拟推送，不依赖交易时段 |
| Production | GitHub Pages 前端 + HTTPS Python 后端 | 云端常驻、存持仓数据库、接入微信 |

## 2. 代码和 GitHub

1. 将 `stock-radar/` 推送到新的 GitHub 仓库，初期建议私有。
2. `git status --ignored` 检查 `.env`、`reports/`、`*.db`、日志不被追踪。
3. 如果密钥已经误提交，**即刻废除并重发**，光删文件不足以清理 Git 历史。
4. GitHub Actions 仅用于前后端单元测试与前端构建；生产部署需要用户手动配置 Secrets/Variables。
5. GitHub Pages 若使用 `/stock-radar/` 子路径，需要 Vite `base: '/stock-radar/'`，静态路由需 Hash Router 或 404 兜底；自定义域名再调整。

## 3. 后端部署

推荐 Linux（有持续运行进程能力）部署 Python 3.11+，FastAPI 由 `uvicorn` 运行，反向代理/平台提供 HTTPS。单实例服务中 APScheduler 使用实例级锁避免多进程任务重复；`uvicorn --workers 1` 或将调度器独立为唯一 worker。不允许多个进程各启动一份 scheduler。

SQLite DB 放持久化磁盘，不使用无持久盘的免费容器运行时；启用 WAL，控制数据库权限；按周安全备份私有位置，备份必须包含验证恢复步骤。未来需要多实例时改 PostgreSQL 和任务锁。

必须有 `/api/v1/health`，服务异常自动重启。对数据源错误、通知失败、任务超时设置可查日志与异常摘要。

## 4. 身份验证与访问控制

**不能把公开 GitHub Pages 当作私有安全页面**：前端代码任何人可读，核心安全在后端。

- 后端提供密码登录；密码用 Argon2 哈希、失败登录限速；短期访问令牌；无默认弱密码。
- 任何持仓管理与历史记录 API 都需鉴权；CORS 精确列出已部署前端来源。
- 不允许无权限请求触发昂贵的行情 API。
- API Key/SendKey、持仓数据库存后端；不输出到前端构建产物、浏览器控制台或错误堆栈。
- 日志中股票代码可仅用于私有诊断；公开 CI 不打印持仓和密钥。

## 5. 外部 API 限额保护

- 同花顺 A 股 ≤10 个代码一组，优先批量历史查询+缓存。
- 指标日线不需要分钟查询；默认每天最多 1 次计划检查及数据尚未更新时 2 次延迟重试。
- B 股 AKShare 要控制请求频率，失败按指数退避，不抓取全市场。
- 通知免费 5 条/天，优先合并；超过当日额度可只更新页面并记录 `NOTIFICATION_QUOTA`。
- 健康任务和用户按键操作均有并发限制和冷却时间。

## 6. 运行状态与故障操作

| 情况 | 处理 |
|---|---|
| HTTP 401/403 | 暂停当前源重试、检查 Key；不生成新信号 |
| 第三方限流 429 | 有上限地退避，不连续轰炸 |
| 收盘日线未更新 | 记录 STALE，稍后重试；旧行情不产生新事件 |
| B 股数据空 / 网页结构变化 | 只标记该股票错误，其他股票继续 |
| Server酱失败 | 记录状态，有限次重试；同 event 不重复发 |
| 云服务器宕机 | 重启后根据最新 bar_date 补做当日检查，但历史补算默认**不补发过时的卖出提醒** |
| 手机无法访问 Pages | 用备用网址或替换静态托管，不修改后端取数逻辑 |

## 7. 发布/回滚检查

每次发布前执行测试、环境变量检查、备份数据库；发布后人工查看 `/api/v1/system/status` 和最近任务，并触发一条模拟通知（生产环境需要单独测试模式，不可制造真实持仓信号）。如果新版本不能正常读库或计算结果异常，回滚应用版本和数据库迁移，仍保留审计事件。

## 8. 当前版本的部署步骤

1. 在已有的 Linux 主机部署代码、Python 3.12 和 uv。使服务用户拥有项目的 `data/` 目录，在项目根运行 `uv sync --locked --extra server --extra probe`。
2. 复制后端环境模板，填写行情凭据和可选 SendKey。使用 `chmod 600 .env` 并由服务用户执行 `.venv/bin/python scripts/admin_password.py`。保留原有配置时跳过复制。公开页面的 CORS 来源填写 `https://lipume.github.io`。
3. systemd 单元示例如下。假定仓库位于 `/srv/stock-radar`，专用服务账号名为 `stockradar`。完成路径和权限检查后安装单元、执行 daemon-reload 并启用服务。

```ini
[Unit]
Description=Stock Radar
After=network-online.target

[Service]
User=stockradar
WorkingDirectory=/srv/stock-radar
ExecStart=/srv/stock-radar/.venv/bin/python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8765 --workers 1 --env-file /srv/stock-radar/.env
Restart=on-failure
UMask=0077
NoNewPrivileges=yes

[Install]
WantedBy=multi-user.target
```

4. 在持有域名的 HTTPS 反向代理上转发到 `127.0.0.1:8765`。例如在 Caddy 的域名配置块中加入 `reverse_proxy 127.0.0.1:8765`，验证 `https://你的域名/api/v1/health` 返回 200，匿名访问 `/api/v1/holdings` 返回 401。
5. 在 GitHub 仓库 Settings → Pages 选择 GitHub Actions。在仓库 Actions Variables 添加 `VITE_API_BASE_URL=https://你的域名/api/v1`，重新运行 Test and publish Stock Radar。仅有前端时可查看未连接提示。真实 Key、SendKey、登录密码及哈希仅在后端配置。
6. 备份使用 SQLite 在线快照，恢复命令要求新的目标文件。先验证副本，再停服务、将 DATABASE_URL 指向恢复的文件并重启。原库可供回退。

```sh
.venv/bin/python scripts/database_copy.py backup data/stock_radar.db data/backups/snapshot.db
.venv/bin/python scripts/database_copy.py restore data/backups/snapshot.db data/restored.db
```

管理员在本机需要改密码时运行 `.venv/bin/python scripts/admin_password.py --reset`，重启服务可立即使所有已有会话失效。数据库备份及密码哈希分别保存于受访问控制的位置。

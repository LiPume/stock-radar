## 必须做出的产品

- **手机首页**：“持仓雷达”标题、最近检测时间、持仓数、预警数、数据异常数；按风险等级排序的持仓卡片，包含股票名/代码、RSI6/12/24、信号状态、价格数据日期。
- **股票管理**：输入六位股票代码，明确上海/深圳和 A/B 属性（自动识别与用户确认结合）；新增、停用、删除、备注；后台持久化。
- **股票详情**：近期日 K 线 + RSI 三条曲线 + 20/80 参考线、最新信号理由、信号历史。
- **手动检测**：按钮发起后端任务，展示执行/完成/失败状态；防止重复并发和刷 API。
- **自动检测**：中国 A/B 股交易日收盘后（默认 15:45 Asia/Shanghai）一次主检查，数据没更新则有上限延迟重试；业务失败时清晰展示状态。
- **微信通知**：Server酱 Turbo HTTP 推送；同一批触发多个股票/规则合并一条；同事件同日只通知一次；记录服务商响应与错误。
- **登录与安全**：初期单用户账号；未授权不能看持仓和触发检查；明文密钥不能到前端。
- **数据可替换**：A 股同花顺官方金融数据 REST；B 股 AKShare；两者均由后端调用；如果源不支持某股票，显示数据源错误而不是虚假信号。

## 固定技术栈

- frontend: Vue 3 + TypeScript + Vite + Vant 4 + ECharts + vite-plugin-pwa；手机优先视觉，适配 360–430px 宽度，桌面也可用。
- backend: Python 3.11+ + FastAPI + Pydantic + SQLAlchemy 2 + Alembic + SQLite(WAL) + APScheduler + httpx；核心 RSI/规则为可测试纯函数。
- auth: 单用户密码（Argon2 hash）+ 短期访问令牌 + 登录限速；前端令牌优先放内存，重新打开可以重登。不使用公开只读无认证接口暴露持仓。
- charts: Apache ECharts 绘制真实历史 K 线和 RSI 指标，明确数据源和最后更新时间。
- notify: Server酱 Turbo（服务端 SendKey；未来可替换别的通知适配器）。
- frontend hosting: GitHub Pages（注意项目子路径 `base`、路由刷新策略、PWA manifest 和 service worker）；backend hosting: 常驻 Linux HTTPS 服务，提供可复制配置步骤，不要把 Python 放进 Pages。
- 建议先不引入 Redis/Celery/PostgreSQL/Docker Compose 等重型设施；如有充分理由可添加，但应有对当前 6 只持仓的明确价值。

## V1 RSI 指标与告警的精确定义

- 日 K 收盘价计算 `RSI6/RSI12/RSI24`，前复权同一口径；参考 `src/stock_radar/indicators/rsi.py` 中的 Wilder 平滑版本。
- `R1/关注`：前一日 RSI6 `<=80`、本日 RSI6 `>80`；持续 >80 不重复发新事件，但前端可显示“当前超买”。
- `R2/风险预警`：前一日 RSI6 `>=` RSI12、今天 RSI6 `<` RSI12，且**前一日 RSI6 >=70**（70 是项目可配置高位门槛）。
- 事件唯一键 `holding_id + bar_date + rule_code + strategy_version`；同日重新检测不重复发。
- RSI **超买 ≠ 超卖**；RSI<20/30 不作为本项目卖出条件。
- 双重顶、顶背离先写可扩展接口/占位说明，**V1 禁止用含糊启发式直接上线**。
- 用至少 100 根历史日线、同花顺同复权口径截图核对指标；计算差异若明显，输出对齐报告、实现兼容方案，不要偷偷改阈值。
- 规则只产生“关注风险”的提醒，不能下单或给出确定性卖出指令。

## 架构与实施顺序（必须逐里程碑完成并测试）

### M0：读取工程并核对数据验证结果

检查 `reports/接口实测报告.md` 是否存在，API 能否实测，环境变量配置。未实测的源只能标记“待接入”。先运行既有 `python -m unittest discover -s tests -v`。

### M1：后端数据层与业务层

建立 `backend/` 正规 Python 包、配置模块、统一数据模型 `DailyBar`、A/B Provider 适配、数据校验、SQLite ORM/Alembic 迁移、持仓管理与指标缓存。API Key 仅后端读取。明确 A 股批量端点参数及响应 group 结构；B 股使用 `stock_zh_b_daily`。引入短期缓存，避免重复拉 240 天。

### M2：RSI 和任务管线

完善 RSI 模块、规则评估、事件幂等写入、正常/缺数据/数据滞后区分；APScheduler 只启动一个调度实例，调用历史 K 线（**必须用真实收盘日线**），收盘后检查并有限重试。单只失败不影响其他股票。所有执行写 `check_runs`。

### M3：消息与鉴权

实现 Server酱推送、失败与额度保护、合并通知、去重、审计；提供可由管理员手动运行的模拟通知测试，但不能给真实股票制造假交易信号。实现鉴权、登录限速、CORS 精确白名单、HTTPS 部署说明。

### M4：Vue 手机 PWA

设计简洁清楚、对长辈易读的页面：留白、字号足够、红色仅突出真实风险、重要数据突出、操作少。首页和详情、添加/删除弹窗、设置、健康状态。若 API 未接入展示“未连接行情”提示，不能用硬编码假价格伪装。

### M5：GitHub 与部署

配置 CI（Python 单测、前端 lint/typecheck/build），配置 Pages 自动部署步骤/工作流，生成 `frontend/.env.example`（只含公开 API_BASE_URL，不放密钥）。完成后端运行教程（VPS/Linux systemd 可选）、HTTPS/CORS 环境变量清单、初始化管理员指引、数据库备份/恢复脚本和测试命令。

### M6：完整自测

覆盖必要单测/集成测试、模拟 Provider、信号去重、推送失败、旧行情不可冒充新行情；至少生成截图或可审查的前端页面（若当前环境允许浏览器）。最后输出部署步骤与尚需用户填写的信息（真实 Key、Server酱 SendKey、服务器域名）。

## 推荐 API 设计

`POST /api/v1/auth/login`、`GET/POST /api/v1/holdings`、`PATCH/DELETE /api/v1/holdings/{id}`、`GET /api/v1/stocks/{symbol}/bars`、`GET /api/v1/signals`、`POST /api/v1/checks`、`GET /api/v1/checks/{id}`、`GET/PUT /api/v1/settings`、`GET /api/v1/system/status`。统一错误响应与请求 ID，后端返回明确 `provider`、`bar_date`、`fetched_at`、`data_status`。

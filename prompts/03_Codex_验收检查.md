# Codex Prompt 03｜上线前全量验收、安全审核与缺陷修复

你作为独立 QA + DevOps 负责人，检查当前 `stock-radar` 的实现是否满足 `docs/01_需求分析_PRD.md`、`docs/02_概要设计_HLD.md`、`docs/03_RSI策略与计算口径.md`、`docs/05_测试与验收.md`、`docs/06_部署安全运维.md`。

1. 列出 P0、P1 的每项验收条件和代码位置/测试证明；对未完成项标 FAIL，不隐瞒。
2. 执行 Python 单元/集成测试、前端类型检查、构建、可用的 E2E；对失败进行修复并重新测试。
3. 搜索前端/构建产物中的 `HITHINK_FINANCE_API_KEY`、`SERVERCHAN_SENDKEY`、所有硬编码密钥/假行情；检查 `git status` 是否包含真实 DB、CSV、个人持仓。
4. 验证 API 返回：空响应、HTTP 401/403/429、非 0 `code`、外层成功但缺少单个股票组、过旧日线都不能生成新信号。
5. 检查 RSI6 上破 80、RSI 高位死叉规则、持续超买的去重、并发调度的事件幂等，确认双顶/顶背离没有在未经验证前上线。
6. 检查访问保护：未登录访问持仓、手动扫描和修改规则应被拒绝；CORS 必须限制来源；管理员弱密码不得默认启用。
7. 检查 GH Pages 子路径资源加载、PWA manifest/service worker、跨域后端 API 地址、HTTPS 与真机显示。
8. 用模拟 Provider 测试推送，不要把演示价格装成真实持仓告警；若有真实 SendKey，须经过用户明确允许后才发送测试通知。
9. 生成 `reports/验收报告.md`，包含 PASS/FAIL/NOT_TESTED、发现问题、已修复内容、剩余阻断项和上线建议。
10. 如果涉及真实 API Key、服务器地址或其他用户私密凭据，只列出需要配置的环境变量名和配置位置，不要要求用户把值发到对话或提交仓库。

只有 P0 全通过、真实数据验证完成、手机可访问、自动检测和通知闭环测通，才把项目标为“V1 可上线”；否则给出下一步最小修复清单。
